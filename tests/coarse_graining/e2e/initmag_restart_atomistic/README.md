# AdaptiveCG Initmag=4 (restart) capability regression

**Purpose:** production-executable evidence that `do_adaptive_cg Y` accepts
an ordinary UppASD restart-format initial condition (`Initmag 4`), reached
through the real `sd.f95` executable, after
`source/CoarseGraining/adaptivecgproduction.f90:validate_configuration` was
changed (RCG-04B follow-up, see `docs/RCG-04_MOVING_E2E_EVIDENCE.md` section
10.4/10.7) to stop rejecting it. This is a **setup/capability smoke test
only** (`Nstep 1`): it proves the state loads and AdaptiveCG accepts and
reports it, not that any dynamics computed from it is correct — no
moving-dynamics or parity claim is made by this fixture.

**Mechanism:** the same 48-atom, `NA=2`, `ncell 6 2 2` host geometry and
`../jfile` used by every other `tests/coarse_graining/e2e` fixture, with
`Initmag 4` and `restartfile ./restart_seed.out` instead of the usual
`Initmag 3`/`../momfile` broadcast. `../momfile` is still required input
(`source/uppasd.f90` calls `read_moments` unconditionally whenever
`do_fixed_mom /= Y`), but its content is not used by the `Initmag=4` branch
of `magninit` — the restart file is authoritative.

`restart_seed.out` is deliberately **not** named `restart.<simid>.out`
(`restart.cg105ir4.out`): the ordinary production restart writer
(`source/System/restart.f90:prn_mag_conf_iter`) always writes its own final
state to exactly that name at the end of the run, which would silently
overwrite this fixture's tracked input on every test run if the names
collided. `simid` is also kept to UppASD's 8-character `character(len=8)`
field width (`source/Input/inputdata.f90:120`) rather than the 9-character
name used during this fixture's development, which Fortran silently
truncated instead of rejecting.

**Restart-file provenance:** `restart_seed.out` is generated
deterministically by
`tests/coarse_graining/moving_state_generator.py:domain_wall_pair_state`
(RCG-04B), not hand-written or copied from a prior run's own output. It is
committed (checked in), not regenerated by the test, per this document's
"decide explicitly whether generated moment files are checked in or
regenerated" requirement — a single small, tracked file is simpler to audit
than a generation step inside the CTest harness for this one-off capability
smoke test. Exact generator invocation, recorded in
`GENERATOR_MANIFEST.json` (including the content SHA-256, reproducible by
calling the same function with the same parameters):

```python
import moving_state_generator as gen
geometry = gen.Geometry(na=2, n1=6, n2=2, n3=2,
                         basis=((0.0, 0.0, 0.0), (0.5, 0.5, 0.5)))
state = gen.domain_wall_pair_state(
    geometry, axis_cell_index=0, wall_centers_cells=(1.5, 4.5),
    width_cells=0.3, moment_magnitude=2.23, simid="cg105ir4",
)
```

The specific wall parameters were chosen only to be a genuinely
non-uniform, non-trivial-to-hand-write restart file exercising every atom
row of the reader (`source/System/restart.f90:read_mag_conf_std`); this
fixture does not itself assert anything about wall position, motion, or
physics — see the domain-wall-pair generator's own unit tests
(`tests/coarse_graining/test_moving_state_generator.py`) for that.

**Negative control:** before the `validate_configuration` fix, this exact
input rejected with `initmag=4 restart is unsupported until adaptive state
serialization is implemented` (the message removed by the fix; reproduced
by temporarily reverting the source change and rerunning). After the fix,
`run_production_e2e.py` asserts `returncode == 0`,
`"AdaptiveCG: capability accepted"`, and
`"AdaptiveCG: initial_state_source=initmag mode=4"` in stdout.
